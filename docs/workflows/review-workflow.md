# Review Workflow

## 1. Preparação
- Garanta que o código passa no lint e build localmente.
- O autor deve revisar seu próprio diff antes de solicitar revisão externa.

## 2. Checklist de Revisão
- Utilize o `docs/review/review-checklist.md`.
- Verifique conformidade com as `architecture-rules.md`.

## 3. Feedback
- Comentários devem ser técnicos e objetivos.
- Priorize correções de segurança, performance e regressão.

## 4. Aprovação e Merge
- O código só deve ser mergeado após aprovação e validação total dos testes.
